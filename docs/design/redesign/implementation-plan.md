### Предложение Claude: ещё не утверждено

- **Рисовать меньше.** Дорисовать в HTML только то, что меняет вид: панель фильтров, дерево доменов, вкладку «Связь» и плотные строки. Окна настроек, блокировок и истории сначала оставить рабочими и перекрасить через новые палитры. Перенос этих окон в разделы — отдельным шагом.
- **Выпускать частями.** Программа должна работать после каждого шага: 0.9.0 — палитры и оболочка, 0.9.1 — таблицы и поиск, 0.9.2 — «Обзор» и остальные разделы.
- **Не обещать данные, которых нет.** Для ленты «Что изменилось» нет общего журнала событий. Сначала решить, откуда она берёт данные, или отложить её. На графике при VPN использовать подпись «До интернета через VPN».

## Этап 4. Привязать данные и действия

1. Сохранить `DestinationRow.Matches` и текущие возможности поиска. Семантику числовых запросов уточнить по аудиту, а не переносить упрощённый JS-поиск целиком.
2. Переиспользовать `CopyIpCommand`, `CopyDomainCommand`, `CopyRowCommand`, `CopyNetworkCommand`. Зафиксировать контракт полной строки; учесть несколько доменов, IPv6, группы и выделение.
3. Не превращать нажатие кнопки копирования в переход, блокировку или потерю выделения.
4. Экспорт должен использовать текущий отфильтрованный набор и существующий `Export.Build`. Нельзя заменять C#-алгоритм демонстрационной арифметикой JavaScript.
5. Передавать выбранную строку в диагностику, RDAP, PeeringDB и блокировки. Особое внимание общему списку: выбранный адрес не должен подменяться первым адресом ранее выбранной программы.
6. Сохранить фоновое обновление, журнал, уведомления, область уведомлений Windows и установку обновлений.

## Этап 5. Проверить результат

Базовые команды из действующего README:

```powershell
dotnet test tests/NetWatcher.Core.Tests -c Release
dotnet test NetWatcher.sln -c Release
dotnet publish src/NetWatcher.App -c Release -r win-x64 -o artifacts/publish
```

Проверку всего решения и UI выполнять на Windows с .NET SDK 10. Добавлять содержательные тесты для изменённого поиска, выборки, экспорта, маршрутизации команд и сохранения настроек. Новые тесты нужны для изменённого поведения, а не для фиксации каждого отступа в XAML.

Существующие ориентиры: `FeatureTests`, `CidrTests`, `DiagnosticsTests`, `LinkMonitorTests`, `QualityTests`, `BlockTests`, `AlertTests`, `UpdateTests`, `UpdateBindingTests`, `ServerFilterTests`, `LinkFilterBindingTests`. Сначала прочитать их действующее содержимое и не считать само наличие файла успешной проверкой.
